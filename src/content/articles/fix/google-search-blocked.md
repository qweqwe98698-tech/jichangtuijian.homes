搜索框敲进去，页面转半天白屏；或者好不容易打开了，每搜一次都要勾一遍「我不是机器人」，勾完还是同一页。这两种情况看起来都叫「Google 用不了」，成因却完全相反。这一页只处理 Google 搜索本身；如果是所有节点整片超时，先走[节点全部超时的排查顺序](/fix/nodes-all-timeout/)；如果 ChatGPT 也一起打不开，那是[另一类风控问题](/fix/chatgpt-blocked/)。

## 你看到的是哪一种拦截

先对号入座，后面的步骤才有意义：

- **连接超时 / 白屏 / 显示无法访问**：流量没走到 Google。责任在链路、分流或 DNS。
- **页面能开，但反复要求验证**：流量到了，是这个出口 IP 被判定为可疑。
- **能搜索，但结果页面是别的国家的版本、或频繁跳转**：出口地区与你的预期不符，属于线路选择问题。
- **只有某个浏览器/某台设备出问题**：本地环境问题，与机场无关。

## 命中率排序总览

| 顺位 | 疑点                 | 典型现象                     | 判断依据                 |
| ---- | -------------------- | ---------------------------- | ------------------------ |
| 一   | 出口 IP 被大量人共用 | 验证循环，怎么勾都不过       | 换一条出口后立刻正常     |
| 二   | 浏览器里的历史痕迹   | 无痕模式正常，常规窗口不正常 | 清理站点数据后恢复       |
| 三   | DNS 与分流规则       | 白屏或超时，别的网站正常     | 换 DNS 或改规则后恢复    |
| 四   | 线路本身不通         | 全部 Google 域名都打不开     | 关代理直连国内网站也异常 |
| 五   | 账号与设备侧         | 换网络换节点都一样           | 换一台设备后表现不同     |

## 最先做：换一个出口，并确认真的换成功了

验证码循环里，八成的解法是这一步。关键在于**换的必须是不同的出口，而不是同一分组里的另一个名字**——同机房的十个节点在 Google 眼里往往是同一段 IP。

- 换**不同地区**的落地，而不是同一地区的相邻节点。
- 换完之后**先查一次自己的出口 IP 是否真的变了**，再去搜索。很多人换了节点却因为规则命中或连接复用，实际出口没变。
- 如果机场提供不同类型的落地，优先试共享人数更少的那一类。为什么共享程度比「是不是原生」更影响验证频率，见[原生 IP 与各类 IP 的区别](/learn/native-ip/)。

需要说明的是：**Google 的判定规则从未公开**，以上只是使用者层面反复观察到的规律，不是它的内部机制。

## 接着做：清掉浏览器里留下的身份痕迹

如果换出口后无痕模式正常、常规窗口仍然要验证，问题在本地：

1. 清除 google.com 相关站点的 **Cookie 与站点数据**（不必清整个浏览器）。
2. 关闭会改写请求的**扩展**：广告拦截、隐私增强、UA 伪装、脚本管理器都可能让请求特征异常。
3. 检查浏览器**自带的代理或 DNS 设置**是否与系统代理冲突，两套走向不同会让特征更可疑。
4. 换一个浏览器交叉验证：另一个浏览器正常，就锁定在原浏览器的配置上。

## 然后查：DNS 与分流把请求送去了别处

白屏、超时这一类，重点看请求有没有走对路：

- **DNS 污染或泄漏**：域名解析到了错误地址，表现为一直转圈。在客户端开启远端解析（由代理侧解析域名），或改用客户端内置的加密 DNS。
- **规则漏项**：Google 的服务分散在多个域名上，只放行了 `google.com` 而漏掉其他域名，就会出现「首页能开、点进去就断」。用规则组的日志看被放行的是哪些域名，或临时切到全局模式对照——**全局模式下正常，就确认是规则问题**，改法见 [Clash 使用教程](/apps/clash-guide/)。
- **协议适配**：某些网络环境会针对性地干扰特定协议，机场若提供多种协议，换一种试一次即可判断。

## 剩下的可能：账号侧、设备侧与时段

到这一步概率已经很低，但仍值得各花一分钟：

- **系统时间不准**会导致 TLS 握手异常，表现为部分站点打不开。校准一次时间。
- **账号本身触发了保护**：换设备、换网络后仍要求验证到同一个账号，那是账号侧的事，与线路无关。
- **高峰时段**：如果是慢而不是不通，那不属于本页，走[晚高峰掉速的分层排查](/fix/peak-hour-slow/)。

## 反复出现，说明的是共享程度

一条线路如果**每天**都要你勾验证码，那已经不是排查问题，而是这条出口被多少人共用、有没有被滥用过的问题。你能做的是记录：连续几天记下哪些地区、哪些线路类型的验证频率更低，这份记录比任何宣传口径都可靠。如果你的主要用途是 AI 与搜索这类对 IP 干净度敏感的场景，选型思路见 [AI 场景专题](/chatgpt-airport/)。

最后两条安全边界，和排查同样重要：

- **不要用来路不明的免费节点访问需要登录的 Google 账号**。出口由陌生人控制，登录态的风险远大于「能不能打开」这件事。
- **不要把自己的订阅链接发给任何人**，包括在群里求助时。订阅链接等同于你的账户凭证。
