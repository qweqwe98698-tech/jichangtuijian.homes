同一台手机、同一个订阅、同一个节点：连着家里的 Wi-Fi 一切正常，切到手机流量就连不上，或者恰好相反。这种「挑网络」的故障有个好消息——它基本排除了账户、订阅和机场侧，因为那些问题不会区分你用哪种方式上网。

## 先分清方向：哪一边通，哪一边不通

两种方向指向的原因不完全一样，先确认自己属于哪一种：

- **Wi-Fi 通、蜂窝不通**：更常见。多指向蜂窝网络的链路特征、客户端在移动网络下的规则差异、以及系统省电策略。
- **蜂窝通、Wi-Fi 不通**：多指向这条宽带或这个局域网本身——路由器设置、DNS 劫持、单位/校园网的策略限制。

顺带确认一件事：**不通的那一边能正常打开国内网站吗？** 连国内网站都打不开，就是网络本身断了，与代理无关。

## 四宫格交叉验证（三分钟框死责任方）

不要凭感觉猜，用两台设备 × 两种网络跑一遍，把结果填进这张表：

|                                  | 家里 Wi-Fi | 手机流量 |
| -------------------------------- | ---------- | -------- |
| 手机                             | ?          | ?        |
| 电脑（用另一条网络或另一台设备） | ?          | ?        |

- **同一台设备两种网络一通一断** → 网络环境差异，看下面的怀疑对象二、三。
- **同一种网络两台设备一通一断** → 设备侧配置或权限，看怀疑对象一、四。
- **四格全断** → 不是本文的问题，转[节点全部超时的排查顺序](/fix/nodes-all-timeout/)。

## 怀疑对象一：客户端在两套网络下用的不是同一份配置

不少客户端支持按网络类型套用不同策略，切网时会自动换一套规则，而你并不知情。检查项：

- 是否存在「按 Wi-Fi/蜂窝分别配置」「特定 SSID 使用直连」这类开关。
- 是否配置过分流规则，把某些网络下的流量整体放行为直连。
- 是否存在多份配置文件，切网时切到了一份没更新过的旧配置。

**判断依据**：切到全局代理模式再试一次。全局下正常，说明是规则问题而不是连接问题。规则位置见 [Clash 教程](/apps/clash-guide/)与 [Shadowrocket 教程](/apps/shadowrocket-guide/)。

## 怀疑对象二：蜂窝网络对协议与端口的处理不同

移动网络和家庭宽带走的是不同的接入链路，对传输特征的处理并不一致。这不是谁「坏了」，是适配问题。

**判断依据**：在不通的那一边**换一个协议的节点**再试。换完立刻可用，原因就锁定在这里。各类协议的差别见[协议知识](/learn/protocols-explained/)。

同理，换一个端口不同的节点也值得一试——部分网络环境只对少数端口友好。

## 怀疑对象三：DNS 与 IPv6 在切换瞬间留下的残留

切网时系统会更换 DNS，客户端却可能还在用上一套网络的解析结果和旧连接，表现为「切过去要等很久」或「一直连不上但重启就好」。

**判断依据**：手动断开再重连代理，或开关一次飞行模式。立刻恢复就是残留问题，而不是节点问题。

可尝试的调整：打开 DNS 覆写／防泄漏选项；如果只有一边网络启用了 IPv6，在客户端里统一 IP 版本策略往往能消除这种「只在某一边出现」的怪现象。

## 怀疑对象四：系统权限、省电策略与热点

- **VPN 权限**：iOS/Android 都需要授权虚拟网卡，权限被撤销或系统更新后失效时，表现常常是间歇性的。
- **省电与后台限制**：把客户端加入不受限制的白名单，避免它在移动网络下被系统冻结。
- **数据用量限制**：检查系统是否给该应用设置了「限制移动数据」。
- **热点共享**：手机开热点时，代理通常不覆盖转发出去的流量，接热点的设备需要自己运行客户端。

## 反过来：蜂窝正常、Wi-Fi 不通

如果不通的是 Wi-Fi 那一边，把怀疑重心移到这条网络本身：

1. 重启路由器，确认不是设备连接数或临时故障。
2. 换一个 DNS 试，排除路由器侧的解析劫持。
3. 如果是公司、学校、酒店网络，先接受门户认证页再连代理；这类网络对协议的限制通常更严格，换协议的成功率最高。

## 仍然无解时怎么办，以及怎么预防

到这一步还没恢复，用**另一个订阅**在同样的网络下做对照：另一个正常，说明是当前机场在这类链路上的适配问题，可作为选型参考；两个都不正常，问题在你的网络环境。

预防做三件事就够了：把常用的两三种协议各留一个节点在收藏里，切网失败时直接换；关掉你并不需要的按网络分策略开关，减少不可见的变量；选机场时优先看它是否提供多协议入口与线路冗余，判断方法见[稳定性核验指标](/guides/stability-signals/)。
